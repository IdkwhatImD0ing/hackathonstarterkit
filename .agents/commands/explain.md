# /explain

The user has zero programming experience. Explain the following in plain English, as if talking to a colleague who is a doctor, lawyer, or consultant with no tech background.

Topic to explain: $ARGUMENTS

Rules:
1. Start with a one-sentence summary of what this does or means
2. Use analogies from everyday life or professional work (medical charts, legal briefs, business processes)
3. Define every technical term the first time you use it
4. If it is an error message, explain what went wrong, why it happened, and what to do about it
5. If it is code, explain what it does section by section, not line by line
6. Never say "it's simple" or "just do X" because nothing is simple when you are learning
7. End with: "Want me to explain any part of this in more detail?"
